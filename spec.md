# 1. Актори та головні цілі

### Людина

- **Гість:** Unauthenticated User
  - Ціль: Переглядати каталог товарів, категорії, відгуки; додавати товари у кошик.
- **Покупець:** Authenticated User
  - Ціль: Керувати профілем та адресами доставки, вести список бажань (`Wishlist`), оформлювати та сплачувати замовлення, залишати відгуки та оцінки на товари.
- **Адміністратор:** Internal Staff
  - Ціль: Керувати каталогом товарів та критерій, змінювати статус замовлень (`status/payment_status`), перегляти звітність.


### Зовнішні системи

- **Платіжна система:** Зовнішній сервіс (`LiqPay, Apple Pay, Google Pay API`)
  - Ціль: Обробка транзакцій, надсилання webhook-сповіщень про статус оплати.
- **Служба доставки:** Зовнішній сервіс (`Нова Пошта, Укрпошта, Meest Пошта`)
  - Ціль: Валідація адрес, створення товарно-транспортних накладних, трекінг статусів.

# 2. EARS-вимоги

| ID Вимоги | Тип EARS | Тригер | Формулювання вимоги |
| :--- | :--- | :--- | :--- |
| **REQ-USR-01** | Ubiquitous | — | Система забезпечує унікальність та валідацію `email` для кожного акаунта `User`. |
| **REQ-USR-02** | Event-driven | **WHEN** користувач обирає нову основну адресу (`is_default = true`) | Система знімає прапорець `is_default` з усіх інших адрес цього користувача. |
| **REQ-PRD-01** | Ubiquitous | — | Система підтримує валідацію ціни товару `price > 0` та кількості на складі `stock_quantity >= 0`. |
| **REQ-PRD-02** | Ubiquitous | — | Система вимагає унікальної назви `name` для кожної сутності `Category`. |
| **REQ-PRD-03** | Ubiquitous | — | Система забезпечує унікальність пари `product_id + category_id` у сутності `ProductCategory`. |
| **REQ-ORD-01** | Event-driven | **WHEN** оформлюється замовлення `Order` | Система фіксує поточну `unit_price` у `OrderItem`, копіює назву служби доставки та адресу, і зменшує `stock_quantity` відповідного `Product`. |
| **REQ-ORD-02** | Unwanted Behavior | **IF** кількість замовленого товару перевищує `stock_quantity` на складі | Система блокує створення замовлення та повертає помилку про недостатню кількість товару. |
| **REQ-ORD-03** | State-driven | **WHILE** замовлення перебуває у статусі `new`, `pending_payment` або `paid` | Система дозволяє користувачу або адміністратору скасувати замовлення (`status = cancelled`). |
| **REQ-ORD-04** | Unwanted Behavior | **IF** замовлення перебуває у статусі `shipped` або `delivered` | Система відхиляє запити на скасування замовлення. |
| **REQ-WIS-01** | Ubiquitous | — | Система забезпечує унікальність пари `user_id + product_id` у сутності `Wishlist`. |
| **REQ-WIS-02** | Event-driven | **WHEN** значення `stock_quantity` товару стає більше 0 | Система автоматично оновлює прапорець `in_stock = true` у таблиці `Wishlist`. |
| **REQ-REV-01** | Ubiquitous | — | Система обмежує значення `rating` у відгуку `Review` цілим числом у діапазоні від 1 до 5 включно. |
| **REQ-REV-02** | State-driven | **WHILE** відображається список відгуків до товару | Система сортує відгуки за замовчуванням у порядку від новіших до старіших за датою `created_at`. |
| **REQ-DEL-01** | Event-driven | **WHEN** акаунт користувача `User` видаляється | Система видаляє його записи у `Wishlist`, але зберігає записи `Order` для фінансової звітності. |
